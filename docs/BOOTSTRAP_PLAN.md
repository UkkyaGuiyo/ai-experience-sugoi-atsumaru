# 初期構築の設計と実装計画

> **履歴資料（初期構築時点）**：この文書の「Privateを維持」「LICENSEは追加しない」および未完了チェック項目は、初期段階の条件を保存したもの。現行の公開状態・ライセンス・運用規則はroot `AGENTS.md`、`README.md`、`LICENSE`を参照する。過去の計画を現行の停止・変更指示として扱わない。

## 目的と制約

安全に一般化したAI利用経験を、成功・失敗を含む広い分野で再利用できる器を作る。初期段階に実データを投入しない。Privateを維持し、LICENSEは追加しない。個人情報、再識別可能な組合せ、秘密、非公開情報、生会話、生ログ、権利・契約・法令上問題のある情報を保存しない。

## 構成

JSONをKnowledge Entryの正本とし、Markdownは日本語の運用文書と作成ガイドに使う。JSON Schemaと同じ制約を標準Pythonの検査器で適用する。全Repositoryのテキストに危険候補を検査し、機械検査を安全保証と扱わない。人によるSafety Reviewと独立レビューを必須にする。

## 実装手順

- [x] 安全運用文書、全分類directory、Entryテンプレートを作る。
- [x] 必須field、失敗固有field、時点・履歴・根拠・レビュー状態をSchemaに定義する。
- [x] Schema違反、危険候補、禁止ファイル、生会話候補、参照整合を検出する。
- [x] 合成値で各検出と誤検出、Schema整合、Entry件数ゼロを単体テストする。
- [x] 読取権限のみのCI設定を作る。remote上の実行結果は最後の手順で確認する。
- [x] 独立ReviewerがPrivacy、Security、Schema、検査器、CI、AI規則、拡張性をレビューする。
- [x] 指摘を修正し、ローカルテストと検査を実行する。
- [ ] 指定作業branchへ通常commit/pushし、CI・Private・remote SHA・clean状態を確認する。

## 検証の焦点

Schema変更が検査器に取り残されないこと、未対応Schema keywordや読取不能fileを黙って通さないこと、検出内容をログへ漏らさないこと、コード・テストを一括除外しないこと、未レビューのEntryを受理しないことを確認する。実在データから知識を作らず、テスト候補は実行時に組み立てた合成値だけにする。
