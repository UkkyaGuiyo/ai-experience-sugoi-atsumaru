## R20：依頼がキューに入ったことと、担当が動き出したことを区別する

**問題・狙い：** 完了・待機状態の担当へ追加メッセージを送っただけで、作業が再開したと報告する。実際には通知だけが保存され、担当は動いていない場合がある。

**再利用する手順：** 依頼送信、受信確認、実行開始、成果物受領、統合完了を別々に記録する。利用する実行基盤の正式な再開操作を確認し、実行状態または担当の応答で再開を確かめる。再開確認前に代役を増やし、同じファイルへ重複作業させない。

**評価用の対照試験（未実行）：** メッセージは受理するが再開しない代替実行器、正常に再開する実行器、完了済み担当への重複依頼を使う。「依頼済み」が自動で「作業中」へ変わらないことを確認する。

**適用場面：** サブエージェント、ジョブキュー、長期タスクの追加修正依頼。

**限界・誤用防止：** 基盤によって通知と再開の意味は異なる。特定のAPI名や全システム共通の挙動を仮定せず、実際の状態遷移を確認する。

**既存の一般原則からの追加点：** 既存の委譲範囲・統合所有権とは別に、依頼配送と実行状態の取り違えを扱う。
