# 生成物・Editor・ビルド境界

## R01：本体を直す前に、生成済み入力の鮮度を確かめる

**問題・狙い：** 設定を変えたのに生成済みのシェーダーや設定表が古いままで、正しい製品ロジックが失敗したように見える。別のテストが先に生成を済ませた場合だけ通ることもある。

**再利用する手順：** 期待値、現在の設定、生成器の入力、ディスク上の生成物、実際にロードされた生成物を別々に照合する。必須プロパティが存在するかを確認してから本体の振る舞いを評価する。生成し直す必要があれば、所有する検証コピーで準備段階として行い、その状態を試験入力として固定する。

**評価用の対照試験（未実行）：** 生成物に必須項目だけが欠ける合成例と、本体の条件分岐だけが誤っている例を分ける。単独実行、全体実行、順序変更で結果が変わらないかを見る。生成後にロード済み表現も更新されたことを確認する。

**適用場面：** コード生成、シェーダー生成、シリアライズ、キャッシュ付きビルドをAIに診断させるとき。

**限界・誤用防止：** 生成し直して通った事実だけでは原因の証明にならない。誤った期待値や本体の欠陥を、生成物の更新で隠さない。利用者の作業データを自動で再生成する許可でもない。

**既存の一般原則からの追加点：** 一般的な段階別判定ではなく、生成入力の鮮度とテスト順序依存を切り分ける。

## R02：画面を開く操作も、検証対象を書き換え得る

**問題・狙い：** プレビューやInspectorを開くだけのつもりでも、初期化コールバックが移行処理を呼び、共有設定を変更し得る。後から一括保存すると、その変更が意図せずファイルへ残る。

**再利用する手順：** 画面の初期化から移行・保存までの呼び出しを調べる。検証用設定を分離し、保護対象についてディスク内容、関連メタデータ、ロード済み値、未保存フラグを操作前後で確認する。製品に必要な移行処理を削るのではなく、試験側の所有範囲と復元責任を明確にする。

**評価用の対照試験（未実行）：** 画面を開く、閉じる、再描画する、後から保存する、途中で例外が起きる、を別々に試す。値は戻ったが未保存フラグやメタデータが変わった例を成功扱いしない。

**適用場面：** Editor拡張、マイグレーション、プレビュー、GUI自動化。

**限界・誤用防止：** 復元処理にも失敗や同時編集の危険がある。利用者の未保存変更を勝手に捨てず、復元不能なら証拠を保持して停止する。

**既存の一般原則からの追加点：** 既存の非破壊検証原則に対し、画面初期化と遅れて起きる一括保存を具体的に追う。

## R03：ビルド出力の隔離だけでなく、コンパイル入力も固定する

**問題・狙い：** 出力先だけを別フォルダへ変えても、暗黙のファイル探索が別ビルドの生成ソースを取り込み、重複定義になることがある。並行作業中の未完成ソースを参照する問題も別にある。

**再利用する手順：** コンパイラへ実際に渡るソース一覧と参照ライブラリを確認する。必要なら検証専用プロジェクトで入力ファイルを明示し、中間・最終出力を分離する。他担当の未完成ソースを使わず、合意した固定済みの参照物を使い、統合後は最終組み合わせでも検証する。

**評価用の対照試験（未実行）：** 無関係な生成ソースを同じツリーに置く例、隣の作業者が参照先を編集中の例、同名の型を含む異なる参照物の例を用意する。入力一覧の差で失敗を説明できるか確認する。

**適用場面：** 複数プロジェクト、並行エージェント、生成コードを含むビルド検証。

**限界・誤用防止：** 明示入力の検証用ビルドは、本来の製品ビルド設定そのものの合格ではない。最終製品の実ビルドを別に通す。

**既存の一般原則からの追加点：** 共有資源の調整ではなく、暗黙に増えるコンパイル入力と参照版の混在を扱う。

## R04：画像座標と演出座標を分け、最終出力にも表示範囲を適用する

**問題・狙い：** 画像の反転や縦横比補正を演出側の座標へ混ぜると、演出方向まで変わる。最初に余白を透明にしても、後段の座標変形や色チャンネル別の再サンプリングで余白へ色が出る場合がある。

**再利用する手順：** 元の表示領域、画像サンプリング座標、演出用座標を別の契約にする。反転や縦横比補正は画像側へ集約する。余白を透明にする要件がある場合は、元の表示領域から作ったマスクを最終合成後の透明度にも適用し、すべての描画経路を同じ契約で検証する。

**評価用の対照試験（未実行）：** 縦長と横長、表裏が別比率、裏面未指定、反転、座標変形、色分離を組み合わせる。余白の画素と画像内の画素を別に比較し、CPU側の式だけで描画成功としない。

**適用場面：** 画像表示、二面表示、シェーダー演出、サムネイルや枠内表示。

**限界・誤用防止：** 意図的に枠外へ伸ばす演出には別の要件が必要。描画の正しさを確認しても、フレーム時間やGPU負荷の保証にはならない。

**既存の一般原則からの追加点：** 一般的な責務分離に加えて、座標変形後も不変条件を守る最終マスクの確認を扱う。
